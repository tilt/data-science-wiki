# Authoring Style

Use a flexible schema: structure follows the topic. The concept template is a menu, not a mandate.

## Principles

- Prefer subtraction over padding.
- Keep a section only when it says something specific to that page.
- Use examples, formulas, code, diagrams, or references only when they carry real explanatory value.
- Cross-link at the point of conceptual contact instead of adding generic "see also" lists.
- Write for reusable technical understanding, not for keyword coverage.

## Deletion test

Copy the section body next to the same-named section on two sibling pages. If a reader could not tell which topic it belongs to, the section is filler and should be deleted or rewritten into topic-specific prose.

## Good page shape

A strong page usually has:

- a direct definition or framing paragraph
- the mechanism, decision rule, formula, or workflow that makes the topic useful
- at least one concrete scenario, calculation, artifact, or operational implication
- links to prerequisites and neighboring concepts where they are needed
- references when factual claims depend on external sources

It does not need every possible section. Remove empty structure before adding prose to satisfy a template.

## Code is a demonstration, not the explanation

A code snippet confirms and makes concrete an idea the prose has already
explained. It is never the place a concept is first defined.

- **Delete-the-code test.** If every fenced snippet were removed, the page must
  still teach the concept through prose and formulas. If it would not, the
  explanation is under-built — fix the prose, do not lean on the code.
- Explain the mechanism in words and, where the topic is mathematical, an
  understandable formula with every symbol defined. The reader should never
  have to decompile Python to recover what the code means.
- Open a snippet by stating **what it demonstrates and why** ("To show why
  clustering cannot replace supervised detection, …"), not by narrating what the
  code does line by line ("This snippet trains a classifier and prints AUC").
- After the output, interpret it: name the takeaway the numbers illustrate.

## Section index pages and navigation

Each numbered section folder has an `index.md` (`page_type: area-index`) that is
the section's main page and, in Quartz, the first click (the folder header links
to it). Use the shape in `content/_templates/area-index.md`:

- **Overview** — one to three paragraphs of high-level orientation.
- **`## Knowledge map`** — a Mermaid `flowchart` of the section's key topics/groups
  and their internal dependencies.
- **`## Reading path`** — an ordered, annotated list of **every** non-index page in
  the section. This list is the **single source of truth** for the per-page
  forward/back navigation, so it must name each page exactly once by its exact
  same-folder filename. `make check-content` fails if it drifts from the folder.
- **`## Connections`** — cross-section links.

Two footer types are generated by `scripts/gen-nav-footers.mjs` (run
`make nav-footers`; `make nav-footers-check` verifies they are current):

- `> **Section — [<Area>](index):** ← prev · next →` — chapter navigation through one
  section, driven by that section's `## Reading path`. The section name links to the
  section overview; prev/next carry the chapter navigation. Emitted on every page in
  the reading path.
- `> **Learning path — [<Name>](learning-paths.md#anchor):** ← prev · next →` —
  cross-section curated sequences, driven by
  `content/00-home-and-navigation/learning-paths.md`. The path name links to its section
  in that file.

A page may carry both. Do not hand-edit these footer lines; edit the reading path
or `learning-paths.md` and regenerate.

## Formatting gotchas

- **Pipes in table-cell math.** Markdown reads `|` as a column separator, so a
  literal pipe inside inline math in a table cell (for example `$P(s'\mid s)$`
  written as `$P(s'|s)$`) silently splits the cell and corrupts the table;
  Prettier then reflows the broken grid, hiding the cause. Write `\mid` (or
  `\vert`) instead of a raw `|` inside `$...$`. `make check-content` fails on
  this. Display math in `$$...$$` blocks is unaffected because it is not inside
  a table row.
- **Mermaid labels.** Keep node labels plain text; avoid parentheses, quotes,
  and raw `|` so diagrams render under the repository's `htmlLabels: false`
  Mermaid patch. Colons and commas inside `[...]` labels are fine.
