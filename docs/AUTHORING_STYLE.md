# Authoring Style

Use a flexible schema: structure follows the topic. The concept template is a menu, not a mandate.

## Principles

- Prefer subtraction over padding.
- Keep a section only when it says something specific to that page.
- Use examples, formulas, code, diagrams, or references only when they carry real explanatory value.
- Cross-link at the point of conceptual contact instead of adding generic "see also" lists.
- Write for reusable technical understanding, not for keyword coverage.

## Deletion test

Copy the section body next to the same-named section on two sibling pages. If a reader could not tell which topic it belongs to, the section is filler and should be deleted or rewritten into topic-specific prose.

## Good page shape

A strong page usually has:

- a direct definition or framing paragraph
- the mechanism, decision rule, formula, or workflow that makes the topic useful
- at least one concrete scenario, calculation, artifact, or operational implication
- links to prerequisites and neighboring concepts where they are needed
- references when factual claims depend on external sources

It does not need every possible section. Remove empty structure before adding prose to satisfy a template.
